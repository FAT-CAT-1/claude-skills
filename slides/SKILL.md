# スライド作成スキル

> 実際に発表資料を2回作り、**2回とも数値チェックが緑のまま崩れを見逃した**経験から作った手順書。
> ここに書いてあるのは意見ではなく、**現物で確かめた失敗と対策**だけ。

## この4つが全部

1. **スライドは字幕ではなく看板。** 読ませない、見せる。文字は話し手が言う。
2. **台本はノートに書く。ノートが唯一の正。** 別ファイルに原稿を作らない（二重管理は必ず食い違う）。
3. **描いて、目で見るまで完成ではない。** 数値チェックは折り返しの崩れを捕まえない（2回とも見逃した）。
4. **既にある pptx を、確認せずに上書きしない。** 本人が PowerPoint で直しているかもしれない。

---

## ⚠ 最優先の警告: 渡した後に、本人が直している

**実際に起きた事故。** 資料を渡した後、本人が PowerPoint で6箇所を直していた
（言い回し・改行・語の置き換え）。スクリプト側は古い文言のままだったので、
**もう一度ビルドすれば手直しが全部消える**状態だった。気づいたのは偶然。

これは「スクリプトで作る」と「当日その場で自分で直せる」の**正面衝突**であって、
不注意ではない。**必ず起きるものとして扱う。**

対策は機構に入れてある —— `Deck.save()` は既存ファイルと中身を比べ、
**食い違ったら上書きせずに止まる**。止まったら:

1. **手直しをスクリプト側へ書き戻して、もう一度実行する**（推奨。以後ズレない）
2. 消えてよいと確認できたときだけ `save(..., force=True)`

⚠ **迷ったら 1。** 相手の手直しは、相手が考えて入れたもの。黙って消さない。
⚠ 久しぶりに触るファイルは、**まず `git fetch` → `git status` → `git diff` で
　 本人の変更と、上流で既に直っていないかを探す。**
　 （実際に、作業ツリーが13コミット古く、上流で解決済みの問題を再発見したことがある）

## 手順

### 0. 作り始める前に、必ず聞く（ここを飛ばさない）

いきなり作らない。最低限これだけは埋まっていないと、作り直しになる:

| 聞くこと | なぜ要るか |
|---|---|
| **何分か／尺は何通りか** | 枚数と密度が決まる。複数あるなら1ファイルで作る（別ファイルは当日の取り違えの元） |
| **聴衆は誰か・専門か** | 専門語を出してよいかが決まる。⚠非専門家なら、一番面白い話が一番伝わらなくなる |
| **話し手が主役か、資料が主役か** | 看板型か説明型かが決まる |
| **会場・投影・画面比** | 明るい教室なら `lecture`／暗室なら `neon`。古い教室は 4:3 のことがある |
| **質疑はあるか** | あるなら予備スライドを末尾に置く（本編には入れない） |
| **絶対に言いたい一言** | ここが決め台詞になる。無いなら締めが弱くなるので掘る |

⚠**「なぜ作ったのか／なぜそれを言いたいのか」が薄いと感じたら、納得するまで掘る。**
本人の言葉より強い材料は無い。一般化した言い回しに置き換えると、必ず力が落ちる。

### 1. 骨格を先に決めて、承認をもらう

いきなり作らず、**枚数・順番・各枚の一言**を表にして見せる。ここで直すのが一番安い。

### 2. スクリプトで生成する（手作業でスライドを組まない）

`example_build.py` をコピーして中身を書き換え、`deck.py` を使って生成する。理由:
- 数字を**出典から機械的に**取れる（手で書いた数字は必ず腐る。実際に腐った）
- 全枚に同じ規則が適用される（1枚だけ書式が違う、が起きない）
- 直して作り直すのが数秒。当日の手直しにも耐える

```bash
python build.py            # 生成
python verify.py deck.pptx png   # 検査（次項）
```

### 3. 検査する ← **この工程がこのスキルの存在理由**

```bash
python verify.py deck.pptx png
```

`verify.py` は PowerPoint →（無ければ）LibreOffice の順で**実際に絵にする**。
どちらも無ければ**「目視していない」と明言して異常終了する**（黙って成功にしない）。

**書き出した画像を、1枚ずつ開いて目で見る。** 見るのは4点:

1. **文の途中で折り返して、末尾の数文字だけが次行に残っていないか** ←最頻出
2. 文字が図形や別の文字に重なっていないか
3. 同じ意味の要素（棒・列・行）の起点と長さが揃っているか
4. 会場の後ろから読める大きさか

⚠**「はみ出し0件」は合格ではない。** 2回とも、はみ出しは0なのに崩れていた。

### 4. 台本をノートに書く

台詞・秒割り・注意は**全部ノートに**入れる。`deck.note()` を使う:

```python
d.board('見出し', notes=note('0:00-0:20', '実際に言う台詞。\n（一拍おく）\n続き。',
                            warn='自己紹介より先にこれを言う', skip=['5分版']))
```

紙の保険が要るときは**書き写さず、機械的に取り出す**:

```bash
python notes_to_script.py deck.pptx 台本.md --変奏 5分版
```

（PowerPoint の「ノート付き印刷」でも同じことができる。好きな方でよい）

### 5. 渡す前に、これを言う

- どのテーマ・何枚・どの尺で何を飛ばすか
- **何を目視したか／していないか**（本番PCで開いていないなら、そう言う）
- 直したいときの手順（スクリプトを直して作り直す、の1行）

## 型とレシピ（全部、実機で描いて確認済み）

### 型1: 看板 `board()` — 話し手が主役の発表
1枚に大きな1行。補足は小さく1〜2行まで。

### 型2: 説明 `explain()` — 図表・箇条を見せる回
見出し＋中身。**箇条は6個まで**（超えると看板ではなく資料になる。`deck.py` が警告する）。

### レシピ
| 呼び方 | 使う場面 |
|---|---|
| `bars()` | 割合・スコアの比較。**軸は全行で共有される**（同じ値は必ず同じ長さ） |
| `compare()` | 2つの対比を1枚で。⚠どちらの列が何かを必ず書く |
| `table()` | 役割・対応・定義の2列表 |
| `steps()` | 手順・変化を → でつなぐ。5個まで |
| `numbers()` | 実績・規模の数字を並べる |
| `blank()` | デモ中・間を取る時。背景だけ |

### テーマ（すべて読みやすさを計算で確認済み・本文4.5以上）
| 名前 | 使う場面 |
|---|---|
| `lecture` | **大学の講義・学術発表（既定）**。明るい教室でも読める白背景 |
| `neon` | 作品・クリエイティブ系の発表。暗室前提の黒背景 |
| `business` | 提案・ビジネス。落ち着いた紺 |
| `mono` | 印刷・コピー・プロジェクタが弱い会場。色に頼らない |

### 文字装飾
`*強調*`＝アクセント1 ／ `**強調**`＝アクセント2 ／ `~控えめ~`＝薄い色 ／ `\n`＝改行

## 停止条件（勝手に決めず、必ず聞く）

- **事実・数字が確認できない** → 埋めない。出典を聞く。**推測した数字を置かない**
- **本人の体験・動機の核心部分** → 一般化して書き換えない。本人の言葉を使う
- 尺・順番・何を落とすかの判断 → 選択肢＋推奨を出して裁定を仰ぐ
- 相手の専門領域に踏み込む主張 → 断定せず「未検証」と書けるか確認する

---

## 既存の pptx を「直して」と言われたら

1. まず読んで、**画像に書き出して見る**（`verify.py` は既存ファイルにも使える）
2. **少しの修正なら、そのまま直す**（全部作り直さない）
3. **全面的な作り直しなら、スクリプト化を提案する**（勝手に作り直さない）

⚠「1行直して」に対して全部作り直すのは、相手の資産を壊す行為。必ず提案してから。

## 過去の事故（同じ轍を踏まないために）

| 事故 | 対策 |
|---|---|
| **数値チェックが全部緑なのに、行が折り返して数字が1つ取り残されていた**（2回） | 必ず絵にして目で見る。`verify.py` |
| 補足2文を1段落にしたら「る。」だけが次行に残った | 補足は文ごとに段落を分ける（`board()` が自動で分割） |
| 棒グラフを行ごとに組んだら、**同じ72%が違う長さで描かれた** | 軸は全行で共有（`bars()` が保証） |
| 表の右列を固定比にしたら、塊が左に寄って見えた | 列幅は実際の文字から測る（`table()`/`numbers()` が実測） |
| 等分の枠に語を置いたら、長い語で矢印とぶつかった | 語は実測幅・矢印は専用枠（`steps()` が対応） |
| 4:3 を 16:9 で書き出して、歪んだ絵を見ながら検査していた | 書き出し比はスライドから取る（`verify.py` が対応） |
| 日本語だけ別の書体に化けた | `a:ea`/`a:cs` を明示（`deck.py` が自動） |
| **渡した後に本人が PowerPoint で6箇所直しており、ビルドし直せば消える状態だった** | `save()` が既存ファイルと比べ、食い違えば上書きせず止まる |
| 手で書いた数字が既に古くなっていた | 数字は出典から機械的に取る（`git rev-list` 等） |
| 旧版の資料を当日うっかり掴みかけた | 差し替えた資料の冒頭に「破棄」と書く |

## 環境の落とし穴（Windows）

- **PowerPoint を開いたままだと pptx を上書きできない**（PermissionError）。
  検査で残ったプロセスは `taskkill //F //IM POWERPNT.EXE` で落とす
- **シェルのヒアドキュメント内では `\` が潰れる**ことがある。
  スクリプトを機械置換すると `\n` が壊れるので、**ファイル編集ツールで直す**
- 標準出力が cp932 のことがある。日本語を出す時は `PYTHONIOENCODING=utf-8`

## 必要なもの

```bash
pip install python-pptx          # 必須
pip install pywin32              # Windows + PowerPoint で検査する場合
pip install pymupdf              # LibreOffice で検査する場合
```
